          Backups

          Your journals, this app's data (settings, on-foot scans, surface marks, statistics, the miss log) and your exomastery and codex downloads, in one zip each time.

          …
          A restore is ready. It is applied when the app starts again.

          When

          Confirm a folder first. Nothing is backed up on its own until you do. Any folder works — the one below, another drive, or a USB drive.

          Where

          A folder on another drive, or one OneDrive or Dropbox keeps, survives a failed disk or a reinstall. The app data folder itself does not.

          USB drives work, and are the best choice when the computer has only one drive (most laptops). If it is not plugged in when a backup is due, the launcher says so, and the next backup after you plug it in catches up.

          backups

          Every backup holds everything, so keeping 5 means 5 complete copies; the oldest goes when a new one is made. Files that have not changed are copied from the backup before instead of compressed again, which keeps it quick.

          Also include

          Keys are off by default: a backup gets copied around, and a key in it goes with it. The bio-bodies file comes back by importing the Spansh export again.

          Restore

          App data is put back when the app next starts; every file it replaces is kept in a before-restore folder. Journals go into a folder you choose, and never replace a file that is already there.

            Import Spansh export

            The same importer as feeder -- import-dump: four gates (probe, field lists, id identity, no oversized ids), update-only. Validate first; nothing is written until you tick apply. A galaxy-scale file takes minutes and the app is slower while it runs.

            A newer export is on disk.
